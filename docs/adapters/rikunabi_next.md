## ページ構造メモ

| 種別 | URL パターン |
|------|----------------|
| 一覧 | `https://next.rikunabi.com/job_search/...` |
| 詳細 | `https://next.rikunabi.com/viewjob/{id}/` |

### 一覧ページ

- 求人リンク: `a[href*='/viewjob/']`
- 件数表示: 「1〜100件目を表示中」など
- 次ページ: 「次へ」リンク（100件単位）

### 詳細ページ（`#company-information` テーブル）

| CSV 列 | 取得元 |
|--------|--------|
| 企業名 | 企業情報「社名」 |
| 郵便番号 | 本社所在地の先頭に 7 桁があれば分割。無ければ空欄 |
| 住所 | 企業情報「本社所在地」（郵便番号を除く） |
| 電話番号 | 「企業代表番号」。無い場合は「お問い合わせ先」。CSV ではハイフン付き |
| メールアドレス | 「メールアドレス」等。ページに無ければ空欄 |
| 担当者名 | 「担当者」。**その他** から始まる場合は空欄。無ければ「代表者」 |
| 掲載サイト | リクナビNEXT |
| 詳細URL | 求人ページ URL |
| 取得日時 | 収集時刻 |

## 運用上の注意

- 一覧は **JavaScript 描画** のため、ページ読み込み後にスキャンする
- `[開く]` 後は **手動で検索** し、**一覧 URL に `/job_search/` が含まれる画面** まで進んでから [収集開始]
- 詳細ページを開いた状態では [収集開始] しない
- 同じ会社が複数求人を出していても、社名と本社所在地が一致すれば CSV は 1 件
- 担当者欄が「その他: …」のような応募案内のときは、担当者名は空欄（行は残す）
- 実装済みリストと電話番号が一致する会社は、チェックオンなら保存しません
- 新規は output の CSV に出し、同じ内容を実装済みリストの末尾にも足します

## テスト手順

1. 収集サイト: **リクナビNEXT** を選択
2. [開く] → ブラウザでキーワード・エリア等を指定して検索
3. 一覧ページ（URL に `job_search`）で [収集開始]
4. フェーズ1で件数カウント → フェーズ2で CSV 出力を確認
